# От заказа с площадки до архива заказчику

Рабочий маршрут: как провести один платный заказ через AgentForge Studio.
Устройство интерфейса и установка описаны в `README.md`, здесь — только порядок
действий.

---

## 0. Один раз, до первого заказа

1. Правая рейка → **Настройки** (нижний значок, открыта по умолчанию).
2. Вставьте ключ Anthropic и/или Moonshot, нажмите кнопку с ключом рядом с
   полем, затем **Проверить ключ**. Ключи шифруются средствами Windows и
   переживают перезапуск.
3. Задайте **дневной бюджет**. Это предохранитель: конвейер сам остановится,
   когда упрётся в лимит, и не выжжет счёт в цикле исправлений.
4. Проверьте **рабочую папку** — в ней будут лежать все проекты.
5. Убедитесь, что установлен **git** (`git --version` в терминале). Тогда
   приложение делает снимок папки после каждого шага, и испорченный файл можно
   вернуть. Без git конвейер работает, но откатываться будет нечем.

---

## 1. Заводим проект под заказ

Один заказ — один проект. Нажмите **«+»** на полосе вкладок и назовите его так,
чтобы через месяц узнать: «Бот записи — Иван, Kwork». Двойной щелчок по вкладке
переименовывает.

Проект — это отдельная папка на диске, свои задачи, своя память и отдельная
переписка со всеми агентами. Ничего из соседнего заказа не подмешается.

Путь к папке всегда виден в строке состояния справа; **Файл → Открыть папку
проекта** открывает её в проводнике.

---

## 2. Готовим текст задачи

Это единственное место, где от вас зависит результат. Всё остальное конвейер
делает сам, но по тому тексту, который вы дали.

Откройте левую панель **Конвейер** (значок ▷, открыт по умолчанию) и заполните
поле.

**Что взять из объявления:** суть работы, функции, стек, если заказчик его
назвал, ограничения («без внешних сервисов», «на PHP», «должно работать на
shared-хостинге»).

**Что выбросить:** приветствия, сроки, бюджет, «жду ваших предложений»,
контакты. Это шум, он занимает контекст и сбивает план.

**Что дописать от себя** — то, чего заказчик не пишет, но без чего приёмка
слепая:

```
Что нужно сделать: <суть задачи своими словами>

Стек: <если заказчик указал — сюда; если нет — выберите сами>

Требования:
- <функция 1>
- <функция 2>
- <функция 3>

Что считать готовым:
- package.json со скриптами build и test
- тесты на node:test для основной логики
- README.md с инструкцией запуска
```

Последние три строки важнее, чем кажутся. **Тесты и скрипт сборки — это то, чем
конвейер проверяет сам себя.** Если их не потребовать, модель может их не
написать, проверять будет нечего, и вы получите статус «Написано, но не
проверено» вместо готовой работы. `README.md` попросите сразу — заказчику всё
равно придётся объяснять, как это запускать.

Пример живого прогона, который прошёл целиком:

```
Веб-приложение «список задач». Бэкенд: Express-API на TypeScript — GET /api/todos
возвращает список, POST /api/todos создаёт задачу из {text}, хранение в памяти,
порт 3000. Фронтенд: страница public/index.html и скрипт public/app.js — форма
добавления и список задач, данные берутся из этого API через fetch. Нужны
package.json со скриптами build и test, tsconfig.json и один тест на встроенном
node:test для логики хранилища задач.
```

## 3. Запуск и утверждение плана

Нажмите **«Запустить конвейер»**. Через 30–60 секунд Admin вернёт план, и работа
остановится — это единственная остановка за весь заказ.

В окне плана проверьте:

- **Ничего не забыто.** Если заказчик просил экспорт в Excel, а в плане его нет —
  допишите подзадачу, а не надейтесь, что «само получится».
- **Исполнители расставлены разумно.** Worker1 — интерфейс и клиент, Worker2 —
  API, данные, инфраструктура. Формулировки и исполнителя можно менять прямо
  здесь.
- **Порядок.** То, от чего зависят другие подзадачи, должно идти раньше:
  конфигурация и модели данных — до сервера, сервер — до страницы.
- **Объёма не слишком много.** 10–12 подзадач для заказа на пару тысяч рублей —
  признак, что задача поставлена слишком широко. Дешевле переписать текст и
  запустить заново, чем платить за работу не по делу.

Правка плана здесь стоит минуту, а разбор десятка файлов, написанных не по тому
плану, — полчаса и деньги.

Кнопка **«Остановить»** отклоняет план и закрывает окно.

## 4. Пока конвейер работает

Вмешиваться не нужно. В журнале видно, что происходит:

```
[Worker2] Записан src/store.ts
[ok] Снимок 09a9432: feat: Хранилище задач и тесты
[Tester] Прогон сборки и тестов
[Tester] Проверки пройдены
```

Панель **Файлы проекта** обновляется сама — файлы появляются по мере написания.
Чаты Worker1 и Worker2 показывают только код, без пояснений.

Ориентир по времени и деньгам: заказ из 4 подзадач с TypeScript и тестами — это
примерно 6 минут и $0.03. Проверенные прогоны укладывались в $0.03–0.07.

Конвейер один на всё приложение: пока идёт один заказ, второй запустить нельзя.
Переключаться между вкладками проектов при этом можно свободно — работа не
собьётся и файлы уйдут в свою папку.

Если закроете приложение посреди работы, прогон пометится прерванным. План,
который ждал утверждения, переживает перезапуск — утвердить его можно и после.

## 5. Три исхода

| Статус | Что это значит | Что делать |
|---|---|---|
| **Готово** | Код написан, зависимости встали, сборка и тесты прошли | Переходить к приёмке (шаг 6) |
| **Написано, но не проверено** | Код есть, но запускать было нечего: нет ни `package.json`, ни `requirements.txt` | Не отправлять как есть. Дописать в чате воркеру недостающий манифест или перезапустить конвейер с явным требованием тестов |
| **Не удалось** | После трёх попыток исправления что-то из трёх: не проходит сборка, приложение работает неправильно (не запускается, отдаёт ошибки, роняет страницу), либо Тестер настаивает на критическом дефекте | Открыть журнал и чат Тестера: там написано, что именно сломано |

«Не удалось» — не поломка приложения, а честный отказ принять негодную работу.
Это ровно то, за что вы платите: заказчик не должен получить то, что не
собирается.

## 6. Приёмка своими руками

Конвейер проверяет сборку, типы и тесты, а веб-приложение вдобавок поднимает:
запускает его вашей же командой, открывает страницу в скрытом браузере, ловит
ошибки консоли, стучится в найденные endpoint'ы кривыми запросами — и **проходит
главный пользовательский сценарий**: Тестер смотрит на страницу, описывает путь
(заполнить поле, нажать кнопку, увидеть результат), и этот путь проигрывается
кликами. Всё это в журнале строками «Запуск приложения и проверка запросами» и
«Сценарий пользователя: пройдено шагов N из M».

Отдельным шагом идёт **оформление**: измеритель снимает с живой страницы
контраст текста, разницу кеглей, разнобой отступов, длину строки, размер
кликабельных зон и переполнение по горизонтали. Замечания уходят агенту-дизайнеру
вместе с дизайн-системой, он правит только CSS и разметку, страница
перечитывается и обмеряется заново — в журнале видно «было 6, стало 1».
В конце делается снимок готовой страницы, он показывается в панели конвейера.

Чего он по-прежнему не делает: не имеет вкуса сверх заданной системы и проходит
один главный путь, а не все ветки. Поэтому перед отправкой:

1. **Панель «Файлы проекта»** — посмотрите, что получилось. Файлы читаются
   прямо в панели.
2. **Панель «Просмотр»** — запускает `npm run dev` в указанной папке и
   показывает результат. По умолчанию стоит `.` — корень проекта. Работает,
   только если в `package.json` есть скрипт `dev`; если его нет, запустите
   проект вручную из папки проекта.
3. **История изменений** — если что-то испорчено, откатитесь. Приложение делает
   коммит после каждого шага, поэтому в папке проекта работают обычные команды:

   ```bash
   git log --oneline
   ```

   ```bash
   git show <хэш>:src/store.ts
   ```

   ```bash
   git checkout <хэш> -- src/store.ts
   ```

   Кнопки отката в интерфейсе пока нет — только командная строка.

## 7. Доделка

**Мелкая правка** — обычный чат с воркером. Выберите Worker1 или Worker2 в
панели «Агенты» и напишите, что поменять. Блок кода с путём (` ```ts
path=src/store.ts `) сохранится в файл сразу, копировать руками ничего не нужно.

**Заказчик прислал уточнение** — запустите конвейер ещё раз в том же проекте,
описав только добавку. Воркеры видят уже написанный код: конвейер собирает для
них дерево файлов и содержимое релевантных, поэтому дорабатывать существующий
проект он умеет.

**Ошибка, которую конвейер не поймал** — опишите её в чате воркеру дословно,
вместе с текстом ошибки. Это дешевле полного перезапуска.

## 8. Архив заказчику

Правая рейка → **Деплой** → **«Экспорт в ZIP»**. Или **Файл → Экспортировать
проект…** — это одно и то же.

В архив попадает вся папка проекта, кроме:

- `node_modules`, `venv`, `.venv` — заказчик поставит их сам;
- `dist`, `build`, `release`, `.next`, `coverage`, `__pycache__` — результат
  сборки, он пересоберётся;
- `.git` — история ваших прогонов, заказчику она не нужна;
- `.env` и подобные — **в них лежат ключи**. Файлы вида `.env.example`
  остаются: заказчику нужен образец, а не ваши секреты. Приложение скажет,
  что именно не включило.

После экспорта в панели видно путь к архиву и число файлов в нём. Число — это
проверка: если там 3 файла вместо тридцати, что-то пошло не так.

**Перед отправкой откройте архив** и убедитесь, что внутри лежит проект, а не
пустая папка, и что туда не уехало лишнее.

Если нужен деплой, сначала нажмите **«Подготовить конфиги»** на той же панели —
Dockerfile, docker-compose, конфиги Railway или Vercel и GitHub Actions лягут в
папку `deploy/` и попадут в архив вместе со всем остальным.

---

## 9. Что отправить вместе с архивом

Заказчику нужен не только zip. Коротким сообщением:

- что именно сделано — списком, по подзадачам из плана;
- как запустить: `npm install`, затем `npm run build` и `npm start` (точные
  команды возьмите из `package.json` проекта);
- что проверено — «зависимости ставятся, проект собирается, тесты проходят»;
- что осталось за рамками, если заказчик просил больше, чем вы взяли в работу.

Если просили README — он уже в архиве, и половина этого сообщения сводится к
«инструкция внутри».

---

## 10. Сколько заказ стоил

Правая рейка → **Токены**: расход по агентам, число запросов, стоимость. Строка
состояния показывает дневной расход и лимит.

Считайте это себестоимостью заказа. **Правка → Сбросить счётчик расходов**
обнуляет дневной счётчик, если хотите считать по заказам, а не по дням.

## 11. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «Конвейер уже занят другим проектом» | Идёт другой заказ. Дождитесь или остановите его |
| План не строится, «Admin вернул не JSON» | Модель Admin слишком слабая или задача сформулирована слишком расплывчато. Смените модель Admin в строке параметров или перепишите задачу конкретнее |
| Статус «Написано, но не проверено» | В задаче не потребованы `package.json` и тесты. См. шаг 2 |
| «Не удалось» с падением сборки | Откройте журнал: там дословный вывод команд. Часто это несовместимые версии зависимостей — допишите нужные версии в текст задачи и перезапустите |
| Экспорт говорит «В папке проекта нет файлов» | Конвейер ничего не записал: посмотрите журнал прогона |
| Просмотр: «В package.json нет скрипта dev» | Обычная ситуация для серверного проекта. Запускайте из папки проекта вручную |
| Конвейер остановился сам | Кончился дневной бюджет. Строка состояния показывает расход и лимит |

## Чего конвейер не делает

Чтобы не обещать заказчику лишнего:

- **проходит один главный путь, а не все ветки** — Тестер описывает главный
  сценарий (добавить, увидеть, отметить), и он проигрывается кликами. Побочные
  ветки, редкие состояния и вторые экраны остаются непройденными;
- **не судит о внешнем виде** — что вёрстка кривая, он не заметит;
- **не поднимает внешние сервисы** — база данных, домен, платёжный шлюз,
  почтовый ящик остаются на вас;
- **не имеет вкуса сам по себе** — дизайнер приводит страницу к заданной
  дизайн-системе (по умолчанию строгой инженерной: светлый фон, один акцент,
  шкала кеглей и отступов) и чинит измеримое: контраст, иерархию, ритм, длину
  строки. Красивее системы, которую вы задали, не станет. Свой стиль опишите в
  промпте дизайнера (панель «Промпты») или в «Памяти проекта» — она
  подмешивается в промпт каждому агенту и главнее системы по умолчанию;
- **не переспрашивает заказчика** — все уточнения возможны только на гейте
  утверждения плана, и задаёте их себе вы сами;
- **не отвечает за смысл задачи** — если в тексте заказа противоречие, конвейер
  спокойно реализует противоречивую версию.
